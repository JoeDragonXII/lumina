Product brief · Technical overview

Lumina

一个本地优先的个人摄影档案系统：让照片、地点、时间和作品集形成可浏览、可管理、可备份的个人记忆空间。

Next.js 16React 19SQLite + DrizzleWindows / macOS / Linux

01 · 产品定义 What and why

产品定位

Lumina 面向希望长期保存和整理个人摄影作品的用户。它把公开展示体验与私有管理能力放在同一个本地应用中，不依赖托管数据库或外部媒体服务。

核心原则是本地优先、数据可控、展示有叙事、功能可验证。

用户角色

  • 访客：浏览首页、图集、作品、时间线和地图。
  • 拥有者：在 Studio 中登录，维护照片、图集、地点和站点设置。

产品目标

  • 降低个人照片整理和回看的成本。
  • 用地点、时间和作品集建立多维入口。
  • 让原始数据和备份始终掌握在用户手中。

03 · 前端特点 Frontend experience

叙事化展示

使用 Next.js App Router 组织公开页面，配合照片墙、背景上下文、分段显现和照片弹窗，让档案更接近一个可漫游的作品空间。

地图探索

提供全球、亚洲、中国、省份、国家和区域层级的地图入口；地图颜色、显示模式和主题可在前端交互中切换。

组件化与响应式

业务组件位于 frontend/modules，通用 UI 位于 frontend/components/ui；布局和交互面向桌面与移动端适配。

技术栈

Next.js 16、React 19、Tailwind CSS v4、Motion、Lucide，以及地图相关的 d3-geo、TopoJSON 和 world-atlas。公开页和 Studio 共享站点配置、导航和媒体 URL 适配层。

可访问的入口

公开区域无需登录；管理区域通过独立登录页和受保护布局隔离，减少管理功能对访客体验的干扰。

04 · 后端特点 Backend capability

数据层

使用 better-sqlite3 与 Drizzle ORM 保存库、图集、媒体、地点和操作相关数据；迁移文件位于 backend/drizzle。

媒体处理

支持常见照片格式和 RAW 处理链路，使用 exifr、ExifTool 和 Sharp 提取元数据、生成预览并管理媒体变体。

领域模块

Library、Media、Map、Studio 和 Operations 分域组织。API 路由只负责协议适配，业务逻辑集中在 backend/modules。

安全与校验

Studio 使用密码和会话 Cookie 保护；输入校验、来源检查、媒体路径和操作参数由后端统一处理。

备份与可恢复性

Operations 模块把 SQLite 数据库和清单写入本地备份目录，便于在不依赖云服务的情况下保留可追踪的恢复点。

05 · 数据与边界 Trust model

默认存储

未配置路径时使用项目目录下的 .local-data/ 和 .local-backups/。可通过 PHOTO_ARCHIVE_DATA_DIR 和 PHOTO_ARCHIVE_BACKUP_DIR 指向独立磁盘或用户指定目录。

真实照片、SQLite 数据库、备份、密码和密钥不应提交到 Git。发布包只包含应用代码、公共资源和示例配置。

运行配置

ADMIN_PASSWORD=your-password
AUTH_COOKIE_SECRET=random-secret
NEXT_PUBLIC_SITE_NAME=Lumina

07 · 本地运行与发布 Operating model

快速开始

pnpm install
cp frontend/.env.example frontend/.env.local
pnpm dev
# http://localhost:3002

Windows PowerShell 可使用 Copy-Item frontend/.env.example frontend/.env.local。

发布边界

开发区可以包含协作文档、测试产物和本地数据；发布包应只保留应用源码、公共资源和示例配置。
